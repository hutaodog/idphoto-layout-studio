## 3. 表3：排版张数矩阵

### 3.1 排版公式（直接照抄）

```python
def grid(paper_px, photo_px, gap_px, margin_px):
    usable = paper_px - 2 * margin_px
    if usable < photo_px:
        return 0
    return (usable + gap_px) // (photo_px + gap_px)   # 整数除法

def layout(PW, PH, wp, hp, gap, margin):
    best = (0, 0, 0, False)
    for rot in (False, True):                          # 必须试 90° 旋转
        pw, ph = (hp, wp) if rot else (wp, hp)
        c = grid(PW, pw, gap, margin)
        r = grid(PH, ph, gap, margin)
        if c * r > best[0]:
            best = (c * r, c, r, rot)
    return best
```

**关键 bug 点**：必须是 `(usable + gap) // (photo + gap)`——这样才表达"n 张照片之间只需 n−1 个间隙"。写成 `usable // (photo + gap)` 会**少算一张**。

居中：`block_w = cols*w + (cols-1)*gap; x0 = (PW-block_w)//2; xi = x0 + i*(w+gap)`

### 3.4 算法选型与留边惯例

**结论：先算"能放几行几列"，再按张数自适应纸型——两步都要。**

1. **用户给纸型** → 由纸型推 `cols×rows`，取最大解（含旋转比较）。
2. **用户给张数** → 从 `[5寸,6寸,7寸,A4]` 选**能容纳且面积最小**者；5 寸够用就绝不排 6 寸（省成本）。
3. **同分决策**：优先**不旋转**（人像正向符合直觉），再优先 `cols ≥ rows`。
4. **余量利用**：LiYing 演示了"左上+右下双布局"填满剩余空间，能多洗几张但**牺牲整齐度**，建议作为可选开关。

**留边 / 出血惯例（C 级，行业惯例）**
- 照片之间留 **2~3mm（24~35px@300dpi）**：太小裁刀会切到邻张，太大浪费纸。
- 纸张四周留 **3~5mm（35~59px）**：这是**打印机不可打印区**（多数家用喷墨四边 3~5mm 不上墨），也是裁切握持余量。**这不是"出血"**——冲印照片没有出血概念，只有不可打印边距。
- **裁切线**：画在照片**边界上**的浅灰细线（Hivision 用 RGB(200,200,200)、1px）或每张照片的黑色矩形框 + 外框定位矩形（LiYing）。**不要画在照片内容内**，否则裁歪会露线。
- **不建议默认加白边**：白边会被误认为证件照底色的一部分，裁切后还容易尺寸超标。

## 5. 必须注意的坑

1. **DPI 元数据必须写，且写错会毁掉物理尺寸。** 同一份 295×413px 文件：标 **300dpi** → 打印 **25.0×35.0mm**（正确）；标 **350dpi** → 打印 **21.4×30.0mm**（**小 8.5%**）。25×35mm 在 350dpi 下真正需要 **344×482px**。落地：JPEG 用 EXIF 写 `XResolution/YResolution` + `ResolutionUnit=2(inch)`（LiYing 用 `piexif`），PNG 直接传 `dpi=(dpi,dpi)` 给 PIL，Hivision 则用 `save_image_dpi_to_bytes`。

2. **⚠️ 已实测的 DPI bug，两库都有：**
   - **LiYing 社保卡/身份证**虽在 CSV 里写了 `Resolution=350`，但其 `get_resize_image_list()` 对**所有**类型都按各自 dpi 算完再与电子像素取 `max()`，一旦下游消费者忽略 per-row dpi 而统一按 300 处理，`2.6×3.2cm` 会被算成 **307×378px**（而非 358×441），或把 358×441 当成 300dpi 文件打印成 **30.3×37.3mm（大 15%）**。
   - **Hivision 社保卡**标 300dpi 的 `441×358`，按 300dpi 解读是 **37.3×30.3mm——根本不是 26×32mm 身份证格式**；按 **350dpi** 解读才是 26.00×32.00mm。
   → **必须把 dpi 作为 per-photo 字段存储，禁止全局常量 300。**

3. **重新压缩会丢 DPI。** LiYing 在压缩完成后**再次**用 piexif 插入 EXIF，说明"先压后写 DPI"是必要顺序。先写 DPI 再走 mozjpeg/pngquant，元数据会消失。**保存后应回读校验。**

4. **色彩空间**：应显式输出 **sRGB**。底色是纯色填充，色彩空间错了 `#628BCE` 会漂成偏紫/偏灰。（注：无任何官方页面明文要求 sRGB，这是工程最佳实践，C 级。）

5. **JPG 质量 vs 文件大小经验模型**（`calc_layout.py` V6）：`字节数 ≈ 像素数 × 系数`，q95≈0.55、q85≈0.35、q70≈0.22。

   | 尺寸 | 像素 | 原始 RGB | q95 | q85 | q70 |
   |---|---|---|---|---|---|
   | 295×413 | 0.12MP | 357KB | 65KB | 42KB | 26KB |
   | 358×441 | 0.16MP | 463KB | 85KB | 54KB | 34KB |
   | 413×531 | 0.22MP | 642KB | 118KB | 75KB | 47KB |
   | 600×600 | 0.36MP | 1055KB | 193KB | 123KB | 77KB |
   | 1051×1500（5寸） | 1.58MP | 4.6MB | 847KB | 539KB | 339KB |
   | 1205×1795（6寸） | 2.16MP | 6.3MB | 1.16MB | 739KB | 465KB |

   **反推**：20KB 只能承载约 **0.06MP（≈204×286px）**。所以"144×192 且 ≥20KB"这类要求**必须靠补字节实现，不能靠降质量**。

6. **"最小文件大小"是真实硬约束，不是玩笑。** 9KB、14KB、20KB、45KB、50KB、150KB 这些**下限**在数据里反复出现。LiYing 的做法是**在 JPEG 的 EOI 之后填充 `\xff\xfe` + `\x00` 字节**把文件撑到目标（`agpic.py::_adjust_file_size`）——广泛使用的合法技巧。**校验器必须同时卡上界和下界。**

7. **人脸占比（构图）——两套默认值不可混用**，因为几何定义不同：
   - Hivision：`head_measure_ratio=0.2`（人脸**面积**/照片面积）、`head_height_ratio=0.45`（人脸中心距顶 45%）、`top_distance_min/max=0.10/0.12`（头顶留白 **10%~12%**）。
   - LiYing：`face_height_ratio=0.30`（人脸**高度**比）、`top_margin_ratio=0.175`（头顶留白 **17.5%**）。
   - 官方唯一几何明文来自 **NCRE**：头 7/10、肩 1/5、上留 1/10、左右各 1/10。**建议以此对齐默认值。**

8. **禁止美颜 / 翻拍。** gov.uk 明文 "unaltered by computer software"（A 级）；NCRE 明文"不得使用生活照、美颜照"（A 级）；研招设图像质量检测+人工退回（A 级）。→ **软件应默认关闭磨皮/美白/瘦脸**（LiYing 的 `--skin-retouch` 默认即关闭），并在 UI 显著提示。

9. **同一名称在不同来源含义不同，不要建全局唯一键**：
   - 「小二寸」：LiYing=33×48mm，Hivision=35×45mm。
   - 「二寸」：LiYing 数值 35×53mm，注释却写 37×49mm。
   - 「教师资格证」：LiYing 同表并列 295×413 与 354×484。
   - 「日本签证」：LiYing 同表并列 531×531(45×45) 与 413×295(35×25)。
   - 「大一寸」：Hivision 与「小二寸」同值。
   → **配置表必须携带 `source` 字段，以 `(用途, 来源)` 复合键索引。**

10. **上传像素 ≠ 打印物理尺寸**（见 §1.4 NCRE）。**同一用途要存两组值，禁止互相换算。**

11. **旋转排版是刚需**：矩阵中大量最优解带 `R`。不做旋转比较会显著浪费纸（7 寸排 1 寸从 18 张掉到 15 张）。旋转后需**垂直镜像校正**人像方向（Hivision 用 `cv2.transpose` + `cv2.flip(0)`）。

12. **Hivision 的自定义尺寸校验规则**（可复用）：`min(h,w) ≥ 100`、`max(h,w) ≤ 1800`、且 **`h ≥ w`**（拒绝横版证件照），毫米输入一律按 `mm/25.4×300` 转 px。来源：`demo/processor.py`
